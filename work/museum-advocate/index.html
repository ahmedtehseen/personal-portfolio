The brief

Move from manually maintained artwork records to museum-owned catalog data.

The original mobile app depended on Airtable for artwork and Firebase for authentication, users, reviews, and media. As the product vision grew, that setup could not support a self-service museum platform or a shared backend for multiple products.

The operating-model shift

Museums could manage profiles, collections, artists, artwork inventory, patrons, and public catalog data instead of relying on the client team as a manual data-entry layer.

Architecture

A shared backend for the dashboard, consumer app, and cataloging workflow.

Museum Advocate became the central API and data layer for museum-owned catalog information, while Firebase Storage remained useful for media files.

Museum Advocate

Next.js, React, API routes, MongoDB, Mongoose, JWT authentication, Firebase Storage, transactional email, and serverless deployment work.

ArtScene

A React Native consumer app consuming public artwork, mobile user, review, rating, and profile APIs.

AI Cataloging

A React Native capture flow connected to authentication, museum-scoped collections, artwork uploads, and cataloging operations.
